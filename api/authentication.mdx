## Authentication

All API requests must include authentication headers otherwise stated:

### Required Headers

```javascript
{
  "X-Auth-Token": "your_jwt_access_token",
  "Content-Type": "application/json",
  "platform": "fincode",
  "uuid": "200"
}
```

### Example Authenticated Request

```javascript
const axios = require('axios');

const response = await axios.get(
  'https://your-company.fincode.software/api/v6/services/admin/organisation-preference-management/fetch-organisation-preference',
  {
    headers: {
      'X-Auth-Token': process.env.JWT_ACCESS_TOKEN,
      'Content-Type': 'application/json',
      platform: 'fincode',
      uuid: '200',
    },
  }
);
```

<Tip>
  Store your JWT tokens securely and implement automatic token refresh to
  maintain uninterrupted API access.
</Tip>

## Request & Response Format

### Standard Request Structure

POST and PUT requests send a JSON body directly. There is no envelope wrapper — pass the fields the endpoint expects at the top level.

### Standard Response Structure

All responses use a consistent `ResultWrapper` envelope:

```json
{
  "status": "SUCCESS",
  "message": "Operation completed successfully",
  "responseCode": 0,
  "errorCode": "0",
  "data": {
    // Response payload (structure varies per endpoint)
  }
}
```

| Field | Type | Description |
|-------|------|-------------|
| `status` | String | See status values below |
| `message` | String | Human-readable description of the result |
| `responseCode` | Integer | Numeric result code — `0` for success, `-1` for failure |
| `errorCode` | String | String representation of the result code — `"0"` for success, `"-1"` for failure |
| `data` | Object | Response payload — structure varies per endpoint |

The `status` field is always one of:

| Value | Meaning |
|-------|---------|
| `SUCCESS` | Request completed successfully |
| `FAILED` | Request failed — check `message` for the reason |
| `ERROR` | An error occurred |
| `PROCESSING` | Request accepted and still being processed |
| `PENDING` | Awaiting further action |
| `PAID` | Payment completed |
| `CANCEL` | Request was cancelled |
| `IGNORE` | Request was ignored |

Failed responses follow the same envelope:

```json
{
  "status": "FAILED",
  "message": "Detailed error description",
  "responseCode": -1,
  "errorCode": "-1"
}
```

## Error Handling

All API endpoints return HTTP 200. Success or failure is communicated through the `status` field in the response body, not through HTTP status codes. Always check `status` before processing `data`.

### Error Handling Example

```javascript
const response = await axios.post(url, body, { headers });
const result = response.data;

if (result.status === 'FAILED' || result.status === 'ERROR') {
  console.error('Request failed:', result.message);
  // result.errorCode will be "-1" for failures
  throw new Error(result.message);
}

// Safe to use result.data
return result.data;
```

## Webhooks

FinCode can notify your application of events via webhooks. Configure webhook endpoints in your dashboard.

### Webhook Events

| Event | Description |
|-------|-------------|
| `TRANSACTION_STATUS` | Fired when a transaction status changes |
| `COMPLIANCE_RISK_PROFILE_UPDATED` | Fired after eKYC is processed and a compliance decision is made |

### Webhook Payload Example

```json
{
  "event-type": "TRANSACTION_STATUS",
  "data": {
    // Event-specific payload
  }
}
```

Register a callback URL for each event type you want to receive in your pay centre configuration.

[Learn more about webhooks →](/api/webhooks)
