---
title: 'Initiate External KYC Provider'
openapi: 'POST /compliance/external-provider/initiate'
description: 'Registers an external KYC provider session with the platform and returns a reference to embed in the provider session.'
---

Use this endpoint when your client uses their own KYC provider instead of the platform's built-in provider.

Calling this endpoint creates a compliance tracking record on our side and returns a unique `reference`. Your client must pass this reference to their KYC provider as the external user identifier (e.g. `externalUserId`, `correlationId`, or equivalent) when starting the verification session.

When the customer completes verification, the provider sends a webhook to the platform. We use the `reference` echoed back in that webhook to match the result to the correct customer record and close the outstanding KYC rule.

## Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `userId` | string | Yes | The customer's user ID returned from the register-customer endpoint |
| `customerEmail` | string | Yes | The customer's email address |
| `ruleId` | string | Yes | The eKYC rule ID from the awaiting compliance requirements list |
| `correlationId` | string | No | Your own reference for this customer (e.g. your internal profile ID). If provided, the platform stores it and uses it to match incoming webhooks when your provider echoes it back as the external user identifier. If omitted, the platform generates a UUID reference instead. |

## Response

The response `data` object contains a `reference` string. If you passed a `correlationId`, the reference echoes it back. If you did not, it is a platform-generated UUID. Either way, pass this value to your KYC provider as the external user identifier so the platform can match the webhook result to the correct customer.

<Note>
  **Option B clients (own KYC provider):** Pass your internal profile ID or user ID as `correlationId`. Your KYC provider must send it back as the external user identifier in the webhook payload. The platform uses this to link the verification result to the customer record.
</Note>
